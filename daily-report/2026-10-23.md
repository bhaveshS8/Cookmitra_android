### Google-only accounts

Google-created accounts have no password by design. The safe fix is an email link that lets the user set one.

Completed:

- Backend now returns `GOOGLE_SIGN_IN_REQUIRED` with actionable copy instead of a dead-end Google-only message.
- Added `POST /auth/set-password` with:
  - Authentication
  - Rate limiting
  - Weak/non-string password rejection
  - Overwrite protection
  - Password hashing
  - `local+google` account linking
- `toUserPayload` now exposes `hasPassword`.
- `getMe` selects `+password`.
- Google auth now loads the password hash so local accounts link correctly.
- App Login screen shows a **Set a password via email** link, prefilled with the normalized email, and routes to Forgot Password.
- App Security screen supports a **Create password** mode for Google-only users and updates Redux after success.

Important behavior:

- A Google-only user must set a password once via the emailed reset link before email/password login works.
- Arbitrary-password login is not allowed because it would bypass account ownership verification.

- Removed the English `formatServiceDate()` formatter.

Updated builders:

- `buildBookingRequestMessage`

- `buildBookingRejectedMessage`

- Accept-confirmation reply in `whatsappController.js`

### Booking request template

- Added `buildBookingRequestTemplateParams()` as the single source of truth for the `new_booking_request` (mr) placeholders:
  - customer → date → weekday → time → duration → address.
- `backend/services/whatsappDispatch.js` now uses the shared helper, so the durable fan-out and the immediate request cannot drift apart again.
- Address parameter now uses the full formatted address (flat/society/landmark/city), not only `booking.address`.

### Immediate request path was still English — fixed

File: `backend/utils/whatsappApi.js`

`sendCookRequestInteractive()` was still using the old English builder, English template values and English button titles, while the durable worker used Marathi. It now:

- Builds the body with `marathi.buildBookingRequestMessage`.
- Sends 6 Marathi template params in the approved reading order.
- Defaults template language to `mr`.
- Uses Marathi buttons: `✅ बुकिंग स्वीकारा` / `❌ नकार द्या`.

Result: no `Date:`, `Venue:`, `Accept ✅`, `Decline ❌`, `AM` or `PM` in the request sent to cooks.

### Other cook replies

- Removed the English `✅ Accepted! cook for me on … 10:00 AM …` lead line from the accept reply and added a Marathi booking-reference line.
- Removed the English `bookingLine()` summary from the ignored/declined replies, which was leaking an English date and AM/PM.

### Address caveat

The address **label** is Marathi (`📍 ठिकाण:` / `📍 पत्ता:`), and the full saved address is shown. The address **text** remains exactly as the customer typed it. English-typed addresses stay English because they are free-form customer data; automatic translation would need a translation/transliteration service. A phonetic transliteration option can be added if required.
